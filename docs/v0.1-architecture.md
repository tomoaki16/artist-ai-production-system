# V0.1 Architecture

## Goal

Studio Oneで最初に検証しながら、将来は複数DAWと複数AI Providerへ展開できる構造にする。

## Architecture

DAWやファイル形式を直接AIへ渡さない。すべての入力を共通Music Contextへ正規化し、AIの提案も共通Proposal形式で受け取る。

```
DAW / Files
  ↓
Input Adapters
  ↓
Canonical Music Context
  ↓
Analysis Core
  ↓
Artist Intent + Constraints
  ↓
AI Provider Adapter
  ↓
Structured Proposal
  ↓
Validation / MIDI Engine
  ↓
Output Adapters
  ↓
DAW
```

## Input Adapters

### DAWproject Adapter

対象：Studio One、Bitwig、Cubaseなど、DAWproject対応環境。

取得候補：

- tempo / time signature
- track / clip structure
- chord information when exported
- notes and note expression
- automation
- embedded or referenced audio
- plug-in metadata

### Standard MIDI Adapter

対象：DAWproject非対応環境および部分的な素材受け渡し。

取得候補：

- notes
- timing / duration / velocity
- tempo / time signature
- track names
- channel information

### Audio Stem Adapter

対象：録音ギター、録音ベース、ボーカル、オーディオ化されたパート。

解析候補：

- onset / rhythm
- density
- register
- monophonic pitch
- polyphonic pitch candidates
- dynamics
- spectral role
- confidence

### Manual Context Adapter

ファイルから取得できない情報をArtistが補足する。

- chord progression
- section labels
- instrument identity
- tuning / capo
- intended role
- performance constraints

## Canonical Music Context

コア内部の唯一の楽曲表現。DAW固有名やAI Provider固有形式を含めない。

主要領域：

- project metadata
- musical timeline
- sections
- harmony
- tracks
- clips
- MIDI notes
- audio analysis
- ensemble statistics
- provenance
- confidence

すべての解析値に、取得元と確信度を保持できるようにする。

例：

```json
{
  "harmony": {
    "source": "daw_chord_track",
    "confidence": 1.0
  },
  "tracks": [
    {
      "role": "bass",
      "sourceType": "audio",
      "analysis": {
        "pitchMode": "monophonic",
        "confidence": 0.86
      }
    }
  ]
}
```

## AI Provider Adapter

AIへ渡すもの：

- 必要な範囲に限定したMusic Context
- Artist Intent
- Constraints
- selected methods
- expected Proposal schema

AIから受け取るもの：

- diagnosis
- musical methods
- alternatives
- rationale
- structured note / part instructions

APIキー、モデル名、通信方法をコアから分離する。

## Validation / MIDI Engine

AIの文章をそのままMIDIにしない。

- schema validation
- time range validation
- harmony constraint validation
- locked-element validation
- playable-range validation
- overlap / collision detection
- deterministic MIDI rendering

## Output Adapters

優先順位：

1. Standard MIDI File
2. DAWproject差分または複製ファイル
3. Drag and drop MIDI clips
4. 将来のDAW固有連携
5. 将来のVST3フロントエンド

## Distribution Boundary

V0.1はクロスプラットフォームのデスクトップアプリとして構築する。VST3はリアルタイム処理コンポーネント向けであり、プロジェクト全体を扱うコアの必須条件にしない。

配布時に必要な境界：

- local project store
- secure credential storage
- explicit data-send preview
- provider-specific privacy notice
- crash-safe autosave
- schema migration
- signed installers
- update mechanism
- diagnostics export without secrets or audio

## V0.1 Vertical Slice

1. DAWprojectを読み込む
2. コード情報とMIDIトラックを共通Music Contextへ変換する
3. 録音Bassのonset / pitch候補、録音Guitarのonset / density / registerを追加する
4. Music ContextをJSONとして確認できる
5. 固定されたサンプルProposalを検証する
6. Proposalから複数パートのMIDIを生成する
7. DAWへドラッグして試聴する

AI接続と本格UIは、この縦切りが成立してから追加する。
